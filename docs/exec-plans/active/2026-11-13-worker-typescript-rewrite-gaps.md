# Worker TypeScript 重写待验证事项

产品要求见 `docs/product-specs/2026-11-13-worker-typescript-rewrite.md`，实施和验收见 `docs/exec-plans/active/2026-11-13-worker-typescript-rewrite-plan.md`。本文记录当前尚缺的证据；完成后将结果写入执行计划并删除对应条目。

## 实施前验证

1. **ONNX 模型文件和缓存：** 当前只交付 `iic/SenseVoiceSmall-onnx`。实验模型 `model.int8.onnx` 与生产 `model_quant.onnx` 哈希不同，FSMN 与 Silero VAD 也不同。核验生产文件能否在候选运行时直接加载，并核验所用文件的授权、下载源、校验和已有缓存升级方式；相同模型家族不能证明文件相同。已完成的实验结论仍须通过正式验收。
2. **ASR 适配接口：** 按 `docs/design-docs/2026-11-13-typescript-worker-asr-boundary.md` 隔离转写接口、模型准备与产物写入。使用当前真实模型验证接口、分段、时间戳和失败语义；本次不实现其他模型或动态插件系统。
3. **下载：** 用户允许官方独立 yt-dlp 内置 Python，作为唯一第三方例外。确认 Windows x64、macOS x64 和 macOS arm64 的资产、版本、完整性、许可及实际启动；对照现有下载参数、来源、字幕、失败、超时和取消行为。官方说明部分独立发行文件采用 GPLv3+，具体资产及分发义务须核实。
4. **TypeScript 运行期：** 现有安装包带 Deno，尚无 Node。先验证当前打包 Deno 对候选原生插件和所需依赖的支持与三平台打包；若不满足，再使用随包 Node。不得依据通用兼容说明推断实际插件可用。
5. **工作间运行器：** `agent_runtime` 为 Python 依赖。需要验证 TypeScript 侧工具循环、工具校验、MCP、planning、skills、checkout、BYOK、错误和取消，涵盖全部现有目标。

## 实施与验收期间完成

- **可复现基线：** `work/asr-spike/` 的语料、结果和脚本未入库；冻结当前 Python ONNX 生产路径的旧版本、依赖、模型与语料哈希、配置和基线结果。私有音视频及文字稿不得未经授权入库；固定指标和脚本时核对不含敏感内容。可从固定旧版本在开发环境重建 Python 基线，发行包不携带该环境。
- **自动质量评价：** 独立参考模型及其文本、语料窗口、单位归一化、漏句和重复判定规则必须在候选测量前冻结；参考文本不能读取或使用候选输出。已有实验的仲裁参考依赖候选输出，不能作为跨候选的固定基准。中文与英文分别验证，缺少适用的独立英文参考时保持未验证；自动参考文本只能作为质量代理指标。
- **协议与宿主：** 迁移仍受支持的 worker 模式和 `storage_validation` 入口，包括 BYOK 测试；保持 stdin 限额、单条 stdout 结果、stderr 事件、错误语义以及 Rust 监督和进程树取消。同步 `contracts/desktop-worker-contract.json`、前端、Rust 和 worker 的模型枚举与版本；新任务只接受 ONNX，历史记录中的旧模型标识仍可读取。
- **设置与旧数据：** 旧 PyTorch 选择一次性迁移到 ONNX 并向用户提示；现有 ONNX 设置及其他设置保持不变，未知值报错。真实旧媒体任务和网页笔记须能读取、续写和恢复；旧模型、缓存及组件文件不能自动删除。升级时旧数据迁移控制记录可能包含 PyTorch 资产，必须验证不加载旧运行时的完整性检查和中断恢复；无法核验时保留源数据和恢复状态。
- **测试与发行：** 将 Python 专属边界测试替换为适合 TypeScript 的等价检查；更新构建资源、运行时指纹、CI、三平台原生依赖及发布冒烟。核实实际安装包体积和现有发布流程，不额外引入双实现常驻或灰度系统。

## 已确认的产品决定

- 只实现现有 ONNX 模型；ASR 使用可替换的模型适配接口。
- 验收全程自动化。
- 自有 worker 不再随发行包携带 Python；官方独立 yt-dlp 内置 Python 获准作为唯一第三方例外。
- 沿用既有本地优先、用户数据、安全、隐私、计费与取消边界。
